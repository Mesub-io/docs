<Endpoint id="listEvents">

Your project's subscription events of the last 30 days, newest first (within one millisecond, by `sequence`, highest first), each the very body its webhooks carry: the same `id`, the same `data`, byte for byte once parsed. Read it to catch up on what an endpoint missed while it was down or turned off.

The 30 days are counted from each call. An event is served once Mesub has written its body, which it does at its first delivery or at the first read here, whichever comes first, and never changes after.

An event whose capture failed is missing from the list until Mesub recovers it: Mesub is alerted, and an event is never served with a later state. Events before `available_since` are not served; every page says `available_since`.

`created_at` is set when the event's transaction begins, a moment before it is visible here: an event can appear below one you have already read. When you poll for what is new, do not stop at the first id you know: page on until `created_at` is a minute older than the newest you held, and skip the ids you have seen.

</Endpoint>
