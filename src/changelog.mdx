The API version is `2026-10-02`, the only one served. Nothing below needs a
new `Mesub-Version`: new codes are added, and your code keeps a default branch
for codes it does not know ([errors](./reference/errors.mdx)).

## 2026-11-11

API v0.1.10, `@mesub/node` 0.1.7, `@mesub/react` 0.1.4 and 0.1.5.

- **A cancelled subscription in the way, named.** `subscription_cancelled`
  on create, a fresh transaction and submit adds `subscription_id`,
  `can_resume` and `closable_from` to the body: the cancelled subscription,
  whether to resume it, and when it can be closed while that is ahead. The id
  is given only when that subscription is the same customer's. See
  [errors](./reference/errors.mdx#a-cancelled-subscription-in-the-way).
- `@mesub/node`: `MesubError` carries them as `subscriptionId`, `canResume`
  and `closableFrom`, null on any other error. The Express and Next widget
  routes hand them on to the browser beside `code` and `message`, and
  `FakeMesub` answers them; `fail()` takes them as `details`. See
  [subscribe](./docs/subscribe.mdx#when-the-wallets-subscription-is-cancelled).
- `@mesub/react` 0.1.5: a checkout refused because the customer's own
  subscription to that plan is cancelled offers Resume it while it runs, or
  Close it and subscribe once it is over, each with one approval in the
  wallet. A refused resume or close says why, with Try again when it is only
  for now. See [React](./docs/react.mdx).
- `@mesub/react` 0.1.5: the dialog keeps its content height in in-app
  browsers that give a modal dialog none, such as Phantom's on iPhone.
- `@mesub/react` 0.1.4, **phones.** A phone's browser sees no wallet app. With no wallet found
  there, the widget no longer offers to install one: it offers to open the
  page in the wallet's own browser, one link each for Phantom and Solflare,
  which leads to the app when it is not installed. Desktop keeps the install
  links. `openInWalletUrl` on `MesubProvider` names the page to reopen, the
  current one by default. See [React](./docs/react.mdx).
- `@mesub/react` 0.1.4: the Phantom and Solflare links show the wallets' own
  logos.

## 2026-11-09

`@mesub/node` 0.1.6 and `@mesub/react` 0.1.3.

- **Four blocked reasons, typed.** `receiver_account_needs_memo`,
  `receiver_account_confidential_only`, `mint_paused` and
  `mint_transfer_hook`. In `@mesub/node`, `explain()` reads each as its own
  situation, with what to do and who does it, instead of `unknown`. The
  widget words them as every other block: payments on hold, nothing for the
  subscriber to do. See [blocked charges](./docs/lifecycle.mdx#blocked-charges).
- `@mesub/node`: `subscription.renewed`'s detail types `amount_received`, as
  `first_payment` does. Book revenue from it.
- `@mesub/node`: `mesub.project()` answers `{ id }`, the project the API key
  belongs to: the quickest way to check that a key works. `FakeMesub` serves
  it. See [retrieve the project](./reference/project/retrieve.mdx).
- `@mesub/react`: `useSubscriptions` gives `hasMore` when the customer holds
  more subscriptions than your server listed, and `ManageSubscriptions` says
  so. A subscription whose past payments could not be read
  (`payments_error`) says so in its window instead of showing none. The
  subscription types carry `next_retry_number` and `retries_allowed`.

## 2026-11-06

API v0.1.8.

- **Shortest billing period per tier.** On the Free and Dev tiers, a plan
  bills at most once a day. Business has no limit. Creating a plan, or
  editing a draft's period, below that answers `period_too_short` (403), and
  so does `prepare_plan` on the MCP server. A published plan keeps its
  period: a project that moves down from Business only cannot create new
  short ones. See [pricing](./docs/pricing.mdx).
- **Checked again at signing.** A draft prepared before, or on a higher tier,
  is refused with `period_too_short` when it is signed: give it a period of a
  day or more. A plan put on chain anyway with a period its tier refuses is
  never served: delete it to take its rent back.
- **A plan signed while its confirmation was lost** (a closed tab, the
  network) is found on chain and published, no longer left waiting.

## 2026-10-29

`@mesub/node` 0.1.4 and MCP server v0.2.2.

- `@mesub/node`: a redirect from the API is never followed, since every call
  carries the API key. The call fails once, as `unexpected`, naming where it
  pointed: check that `baseUrl` is the Mesub API.
- **MCP v0.2.2.** A server that calls another Mesub API than
  `https://api.mesub.io` says so in its instructions: the merchant's server
  sets `MESUB_BASE_URL` to that address beside `MESUB_API_KEY`, both from that
  Mesub's dashboard. `search_docs` searches the docs as of 2026-10-27.

## 2026-10-27

`@mesub/node` 0.1.3 and API v0.1.7.

- `@mesub/node`: `new Mesub()` reads its address from `MESUB_BASE_URL` when
  `baseUrl` is not given, then defaults to `https://api.mesub.io`, as the key
  comes from `MESUB_API_KEY`. The helpers' default client (`mesubRoutes`,
  `requirePlan`, `withMesub`, ...) follows it. An empty variable counts as
  unset. See [the API key](./docs/api-key.mdx).
- The Dev tier's plan shows its logo again.

## 2026-10-25

API v0.1.6, dashboard v0.1.15, MCP server v0.2.0 and v0.2.1.

- **Organizations.** Every Mesub account has a personal organization. You
  can create others and invite members, as Owner, Admin or Member. See
  [organizations](./docs/organizations.mdx).
- **Organization wallet.** It signs the organization's plans and pays its
  Dev tier. Only the Owner sets it.
- **To sign.** Plans and actions wait there for the organization wallet. The
  New plan form ends with **Sign and publish** when you hold that wallet.
- **Tiers change in Billing**, per project.
- **New codes:**
  - `approval_too_low` (409): the wallet caps what its subscriptions in this
    token may take below one payment of the plan. The customer raises the
    cap, then tries again.
  - `comeback_approval_revoked` (409): a return to a stopped subscription
    whose wallet no longer approves the token. Cancel it, close it, then
    subscribe again.
- **Subscribing after a revoke works.** When a wallet revoked or replaced
  Mesub's approval, subscribing makes its authority for that token again. The
  terms say first that this ends every other subscription the wallet has in
  that token. The rent goes back to whoever paid it.
- **MCP v0.2.0.** A connection reaches a whole organization, or one project
  it is pinned to. The tools take `project`, by id or name, and
  `list_projects` lists them. New refusals: `project_required`,
  `project_not_found`, `project_ambiguous`, `project_outside_pin`,
  `project_mismatch`, and `role_required` and `team_wallet_required` on
  `prepare_plan`. See [the MCP server](./docs/mcp.mdx).
- **Words.** Messages say organization wallet, receiving wallet and To sign.
  No code or field was renamed.
- **MCP v0.2.1.** `search_docs` searches the organization docs, and
  `update_webhook` says that disabling an endpoint mails the Owner and the
  Admins.

## 2026-10-21

`@mesub/node` 0.1.2 and `@mesub/react` 0.1.2. They carry the changes of 0.1.1,

- `@mesub/react`: `chain` defaults to `solana:mainnet`.

- A plan's end is shown with its time, in UTC.

## 2026-10-20

API v0.1.3 to v0.1.5.

- `insufficient_sol` (409): the wallet holds too little SOL for the rent, the
  fee and its reserve. Refused before anything is signed, when a plan is
  created or a customer subscribes.
- Token-2022 plans: Mesub reads the token's extensions and records what the
  receiving wallet got, `amount_received`.
- A plan's end takes a time, to the minute, in UTC.
- A `subscription.renewed` delivered late carries the period it paid.

## 2026-10-18

First production release: the API and the MCP server.

- Access events: `subscription.access_granted` and
  `subscription.access_revoked` ([webhooks](./docs/webhooks.mdx)).
- Rotating a webhook secret can keep the old one signing for a while.

## 2026-10-02

API version `2026-10-02`. Before the first integrator, two codes were renamed
within it: `plan_deleted` became `plan_removed`, and `plan_rebuilt` became
`plan_replaced`. The old names are no longer answered.
