`hasAccess` is enough to gate a route. Webhooks are for reacting when something
changes: a renewal, a missed payment, a cancellation.

## Set up your endpoint

In the [dashboard](https://mesub.io/dashboard#developers), open **Developers**,
then **Webhooks**, add your URL and pick its events. Put the endpoint's signing
secret in your server's environment:

```bash
MESUB_WEBHOOK_SECRET=whsec_...
```

An endpoint must be a public HTTPS URL. A project can have up to 16.

## Create a handler

Mesub signs each delivery the [Standard Webhooks](https://www.standardwebhooks.com)
way. The signature covers the exact bytes sent, so verify the **raw body**,
never one a JSON parser read and wrote again.

<CodeGroup>

```ts Express
import express from 'express';
import { Mesub, MesubError } from '@mesub/node';

const mesub = new Mesub(); // reads MESUB_API_KEY and MESUB_WEBHOOK_SECRET

// express.raw on this route, before any express.json() reaches it.
app.post(
    '/webhooks/mesub',
    express.raw({ type: 'application/json' }),
    async (req, res) => {
        let event;
        try {
            event = await mesub.webhooks.verify(req.body, req.headers);
        } catch (error) {
            if (error instanceof MesubError) return res.status(400).end();
            throw error;
        }

        if (await alreadyHandled(event.id)) return res.status(200).end();

        switch (event.type) {
            case 'subscription.renewed':
                // event.data is the subscription, event.data.detail what was paid
                break;
            case 'subscription.payment_failed':
                // event.data.detail: reason, retries_left, next_retry_at
                break;
        }
        res.status(200).end();
    },
);
```

```ts Next.js
// app/webhooks/mesub/route.ts
import { MesubError, verifyWebhook } from '@mesub/node';

export async function POST(request: Request) {
    let event;
    try {
        event = await verifyWebhook(await request.text(), request.headers);
    } catch (error) {
        if (error instanceof MesubError) return new Response(null, { status: 400 });
        throw error;
    }

    if (await alreadyHandled(event.id)) return new Response(null, { status: 200 });

    switch (event.type) {
        case 'subscription.renewed':
            break;
        case 'subscription.payment_failed':
            break;
    }
    return new Response(null, { status: 200 });
}
```

```ts NestJS
// main.ts: keep the raw body beside the parsed one.
const app = await NestFactory.create(AppModule, { rawBody: true });

// mesub-webhooks.controller.ts
import {
    BadRequestException,
    Controller,
    HttpCode,
    Post,
    type RawBodyRequest,
    Req,
} from '@nestjs/common';
import type { Request } from 'express';
import { MesubError, verifyWebhook } from '@mesub/node';

@Controller('webhooks/mesub')
export class MesubWebhooksController {
    @Post()
    @HttpCode(200)
    async receive(@Req() req: RawBodyRequest<Request>) {
        let event;
        try {
            event = await verifyWebhook(req.rawBody!, req.headers);
        } catch (error) {
            if (error instanceof MesubError) throw new BadRequestException();
            throw error;
        }

        if (await alreadyHandled(event.id)) return;

        switch (event.type) {
            case 'subscription.renewed':
                break;
            case 'subscription.payment_failed':
                break;
        }
    }
}
```

</CodeGroup>

Answer with a 2xx within 10 seconds, before any slow work of your own. Anything
else, a redirect included, counts as a failure.

## Test your handler

### See a delivery before writing any code

[webhook.site](https://webhook.site) gives you a public URL that shows every
request it receives. It is the quickest way to see what Mesub sends.

1. Open [webhook.site](https://webhook.site) and copy **Your unique URL**.
2. In the [dashboard](https://mesub.io/dashboard#developers), under
   **Developers** then **Webhooks**, add that URL as an endpoint.
3. Send a test event to it from the endpoint's row.
4. Back on webhook.site, the request appears with its JSON body and three
   headers: `webhook-id`, `webhook-timestamp` and `webhook-signature`.

The signing secret is not in the request. It stays in the dashboard, and your
handler uses it to check `webhook-signature`. Remove the endpoint when you are
done: it would receive your real events too.

### Send a test event to your own handler

In the dashboard, open your endpoint and send it a test event of the type you
choose. A test delivery is signed like a real one and carries `"test": true` in
its body, with a made-up subscription whose id is `sub_test`, so your handler
can recognise and ignore it.

A handler running on your machine needs a public URL. A tunnel such as
[ngrok](https://ngrok.com) gives it one.

## Events

| Event                         | Sent when                                               |
| ----------------------------- | ------------------------------------------------------- |
| `subscription.created`        | The first payment landed                                |
| `subscription.renewed`        | A period was paid                                       |
| `subscription.payment_failed` | A charge missed                                         |
| `subscription.stopped`        | Mesub stopped charging after missed payments            |
| `subscription.cancelled`      | The customer cancelled; access runs to the period's end |
| `subscription.resumed`        | A cancellation was undone                               |
| `subscription.ended`          | It is over; `data.end_reason` says why                  |
| `subscription.expired`        | A checkout was started and never signed                 |
| `test`                        | You sent one from the dashboard                         |

Mesub may add a type later: keep a default branch.

## The event object

Every event has the same shape: its `type`, when it happened (`created_at`),
and `data`, the subscription as `subscriptions.retrieve` answers it, plus
`detail`, which is the event's own. The id to deduplicate on is not in the
body: it is the `webhook-id` header, which the SDK gives you as `event.id`.

## Delivery behavior

### Retries

A delivery that gets no 2xx is sent again for about three days, under the same
`event.id`.

### Duplicates

The same event can arrive more than once. Store the ids you handled and drop a
repeat.

### Order

Order is not guaranteed: a retry can land after a later event. Before granting
or revoking anything, ask `hasAccess` rather than trusting the last event you
saw.
