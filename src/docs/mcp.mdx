## What it is

An [MCP](https://modelcontextprotocol.io) server that Mesub hosts. Your AI tool
connects to it, and its agent can then read the projects of **one
organization** and act on them, the way you would in the dashboard. There is
nothing to install and no [API key](./api-key.mdx) to hand over.

It is not the [agent skills](./skills.mdx). The skills teach an agent to
**write** your integration, in your codebase. The MCP server lets an agent
**act** on your projects: look at a subscription, retry a charge, add a webhook.

The agent acts **with your role** in the organization, read again on every
call. It can use every tool your role allows, and no other. There is no
read-only mode, so connect an agent only if you would let it do all of that.

## Connect

1. Add the server's address to your AI tool, as a remote MCP server.
2. The tool opens a Mesub page in your browser. **Sign in** to the dashboard.
3. Under **Connect to**, find the organization. Choose **Whole
   organization**, or pin the agent to one project under **Or only one
   project**.
4. Read what the page lists, then press **Authorize**.

The address:

<McpAddress />

A tool configured by a JSON file takes an entry like this one:

<McpJson />

Some tools want `"type": "http"` beside the `url`. A tool configured from a
terminal takes the same two things, a name and the address. The words of the
command are your tool's own, this is only its usual shape:

<McpCommand />

Nothing is chosen for you, with one exception. If you opened **Connect agent**
inside a project of the dashboard in the last 15 minutes, that project is
chosen as the pin. You can change it before you authorize.

Once you choose, the page says what the agent will reach, and with which role.
For an organization called Northwind, with the projects Shop and Docs:

- **Whole organization**: "All current and future projects of “Northwind”."
  A project you create later is reached too.
- **Pinned to Shop**: "Only the project “Shop”." The agent never reaches Docs.

The page that asks you to authorize shows the **name the application gave
itself**. Beside it is the host that publishes the application when Mesub
could check one, and **Unverified app** when it could not. The page also says
where your browser is sent back to: check both before you authorize. A request
you leave open is dropped after ten minutes.

A connection reaches one organization. To work on **another organization**,
or on another project than the pin, connect again and choose it.

## What the agent can do

**Read**

| Tool                      | What it does                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_projects`           | The projects the connection reaches, with their id, name and tier, and your role and what it allows                                                                    |
| `get_project`             | One project, its tier, and how much of its limits is used                                                                                                              |
| `list_plans`              | Every plan, with its subscribers and what it collected this period. A prepared plan waits there with its link to sign                                                  |
| `get_plan`                | One plan: its subscribers by status, its latest charges, why charges fail                                                                                              |
| `list_subscriptions`      | Subscriptions, by plan or by status, or found by wallet or by your own customer id                                                                                     |
| `get_subscription`        | One subscription and every charge tried on it                                                                                                                          |
| `check_access`            | Whether a customer has [access](./access.mdx), and why not when they do not                                                                                            |
| `list_events`             | What happened on a day, over the last 45 days: payments, subscribers, changes to the project. Finds a charge by wallet, your customer id or the start of its signature |
| `list_upcoming_charges`   | The charges and retries to come, each one Mesub already expects to fail flagged with why                                                                               |
| `get_overview`            | Collected, failed and recovered over 7, 30 or 90 days                                                                                                                  |
| `list_webhooks`           | The [webhook](./webhooks.mdx) endpoints, never their secret                                                                                                            |
| `list_webhook_deliveries` | An endpoint's deliveries and what your server answered                                                                                                                 |
| `get_webhook_secret`      | An endpoint's signing secret                                                                                                                                           |
| `search_docs`             | Search these docs. It reads nothing of your projects                                                                                                                   |
| `ping`                    | Whether Mesub answers                                                                                                                                                  |

**Act**

| Tool                        | What it does                                                                                                                                                         |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `retry_charge`              | Retry a failed charge, when a customer is [late](./lifecycle.mdx#late-payments). Mesub refuses one that cannot succeed or a wallet short of funds, spending no retry |
| `update_retry_policy`       | Change how many times a plan retries, and how far apart                                                                                                              |
| `create_webhook`            | Add an endpoint and return its signing secret                                                                                                                        |
| `update_webhook`            | Change the URL or the events of an endpoint, turn it off or back on                                                                                                  |
| `delete_webhook`            | Delete an endpoint                                                                                                                                                   |
| `regenerate_webhook_secret` | Draw a new signing secret. The old one keeps signing for `overlap_hours`, 0 to 24: at once by default                                                                |
| `send_test_webhook`         | Send a test delivery to an endpoint                                                                                                                                  |
| `update_project`            | Rename a project                                                                                                                                                     |

**Prepare**

| Tool           | What it does                                                                            |
| -------------- | --------------------------------------------------------------------------------------- |
| `prepare_plan` | Fill in a plan for you. It does not exist until the organization's team wallet signs it |

Before preparing, your agent asks you two things: whether to **lock the receiving wallets** (up to four, and which one is paid for now) and whether the plan **has an end**, a day and a time in UTC. A locked list can never change once the plan is signed. With no list, the plan pays the organization's team wallet, and you can change the receiving wallet later in the dashboard.

**Who signs a prepared plan.** Whoever holds the organization's **team
wallet**. The agent hands you two links: the plan's page, where you review it
and can still edit it, and its entry in **To sign**. The team wallet signs from
either one. In a personal organization, the team wallet is the wallet your
account signs with, until you register another one in Organization settings.

The tools describe their own parameters to the agent, so there is nothing to
learn here: ask in plain words.

## Which project a tool works on

Every tool but `list_projects`, `search_docs` and `ping` takes a `project`: the
project's id, or its name. The agent does not need to know them in advance: `list_projects`
returns every project the connection reaches, none left out. Your agent calls
it when it does not know which project you mean.

When the agent leaves `project` out, the tool falls back like this:

| Tools                                                                                                                      | With `project` left out                                                        |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `list_plans`, `get_plan`, `list_subscriptions`, `get_subscription`, `list_events`, `list_upcoming_charges`, `get_overview` | Every project the connection reaches                                           |
| `get_project`, `check_access`, `list_webhooks`, `list_webhook_deliveries`, `get_webhook_secret`                            | The pinned project, or the organization's only project. Else it is refused     |
| Every tool that changes something, `prepare_plan` included                                                                 | The pinned project. Else it is refused, even in an organization of one project |

So on Northwind, connected as a whole:

- "Which payments failed this week?" reads Shop and Docs together. Each event
  says which project it belongs to.
- "Add a webhook for failed payments" needs a project. The agent asks you
  which one, then calls `create_webhook` with `project: "Shop"`.
- On a connection pinned to Shop, the same request needs no `project`: it lands
  in Shop. Naming Docs there is refused.

A name is matched inside the organization only. The exact name wins; else the
case does not matter, so `shop` finds Shop. When the value names two projects,
the agent uses the id instead. A project of another organization is never
found, even one you are a member of.

Every change answers with the project it acted on: "Project acted on:
“Shop”." The MCP server checks it against the project the agent named. When
they differ, it stops and tells you (`project_mismatch`, below).
`delete_webhook` is the one change Mesub answers with nothing, so it does not
say where it deleted.

## What each role's agent can do

The agent has the rights your role has in the dashboard, checked live on every
call. The Owner's and Admins' agents can use every tool. A Member's agent can
use every tool **except** these:

| Tool                                                                                                   | What a Member's agent is told                                 |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `get_webhook_secret`                                                                                   | "Only the Owner and Admins can read webhook signing secrets." |
| `create_webhook`, `update_webhook`, `delete_webhook`, `regenerate_webhook_secret`, `send_test_webhook` | "Only the Owner and Admins can manage webhooks."              |
| `update_project`                                                                                       | "Only the Owner and Admins can rename this project."          |

A Member's agent still reads every project, checks access, retries charges,
changes a plan's retry policy and prepares plans.

The role is read on each call, never kept in the connection. An Admin demoted
to Member: their agent's next webhook call is refused. Someone removed from the
organization: their agents are disconnected.

## When a call is refused

A refused call returns a Mesub error code, its message and what to do next.
The agent never calls a tool that changes something again because it failed,
unless the error says it is temporary.

| Code                   | When                                                                  | What happens next                                                                                                                                |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `role_required`        | Your role does not allow the tool                                     | The agent relays the message as it is. It does not retry, and connecting again changes nothing. Someone it names can do it, or give you the role |
| `team_wallet_required` | `prepare_plan` in a team organization with no team wallet             | Nothing is prepared. The agent gives you the link to Organization settings. The Owner sets the team wallet there, then the agent calls again     |
| `project_required`     | No `project`, where the table above refuses it                        | The agent calls `list_projects`, asks you which project when it is not clear, then calls again with it                                           |
| `project_not_found`    | No project of the organization has that id or name                    | The agent takes the project from `list_projects`                                                                                                 |
| `project_ambiguous`    | The value names two projects, for example one's id and another's name | The agent calls again with the id                                                                                                                |
| `project_outside_pin`  | A pinned connection named another project                             | You connect again and choose the whole organization, or that project                                                                             |
| `project_mismatch`     | Mesub's answer names another project than the one the agent named     | The agent tells you and stops. The change may have gone through elsewhere: check it in the dashboard                                             |

For example, a pinned connection that names Docs gets: "This connection
reaches “Shop” only. Connect again without a pin to work on another project."

## What it can never do

Whatever the agent is asked, by you or by anything it reads:

- Do more than your role allows.
- Reach a project of another organization, or another project than its pin.
- See or change your **API key**.
- Change a project's tier.
- Delete a project or a plan.
- Close a plan, or change the end or the receiving wallets of a plan already signed.
- Sign a plan. It prepares one; the team wallet signs it.
- Resend an old webhook delivery.
- Read a customer's email. It can check access for an email you give it, and
  never gets one back: a customer is shown by wallet and by your own id.
- Cancel or change a customer's subscription. Only their wallet can.

These are not tools switched off: the server has no such tool, and Mesub gives
an agent no way to them.

## Limits

Per connection: **120 reads** and **20 changes** a minute, and 5 test
deliveries a minute, refused ones included. A connection to a whole
organization has one budget for all its projects.

How many agents can be connected at once:

- **10 per organization** reaching all its projects.
- **10 per project** pinned to it. A connection to the whole organization
  takes none of these places.
- **30 per account**, across everything you connected.

Only live connections count: one revoked, or unused for a day, frees its
place. When there is no room, the consent page greys out that choice, and
Mesub refuses the approval with `agent_connection_cap_reached`. Revoke a
connection first.

## See and cut a connection

In the dashboard, **AI & agents** lists every agent connected to the
organization, whole or pinned. Inside a project, **Developers**, then
**Connected agents**, lists the agents that reach that project: those pinned
to it, and those connected to the whole organization. Each line is one
connection: the application, what it reaches, when it connected, when it was
last used and when it ends.

The Owner and Admins see everyone's agents. A Member sees their own.

- **Revoke** cuts a connection. The agent's very next call is refused.
  Revoking a connection to the whole organization from a project's list cuts
  it from every project, not only that one.
- You can always revoke your own. A Member's agent can be revoked by the Owner
  and Admins; an Admin's or the Owner's, by the Owner only.
- A connection **ends by itself after a day without use**. While it is used,
  it stays open: your tool renews its one hour token by itself.

Cutting a connection undoes nothing: what the agent changed stays as it is.
To connect again, start from your tool.

## Risks

**A signing secret lands in your conversation.** When an agent creates a
webhook, regenerates its secret or reads it, the secret is in the answer, so
it is in the conversation and wherever your tool keeps it. Move it to your
server's environment, and regenerate it if the conversation is shared.

**What the agent reads is written by other people.** A plan's name, a
project's name, what a webhook endpoint answered, the identifier of a
customer: all of it is text somebody else chose, and it can be written to look
like an instruction. The server tells every agent to treat it as data. An
agent can still be steered by it. That is why the tools that move money or
break an integration, such as retrying a charge, deleting a webhook or
regenerating its secret, are marked so that your tool **asks you first**. Keep
that question on, and read it.

**A connection to the whole organization reaches more.** It reaches every
project, those created later included. Pin the agent to one project when it
needs only that one.

**You review every prepared plan.** The agent fills it in, the team wallet
signs it. Read the project, the price, the token, the period, the end and above
all the **receiving wallets** in the dashboard before signing: each one is
shown in full and marked when it is not on your account. You can still edit
the plan there first.
