This page takes an empty project to one paying subscriber. On devnet, with
test money, it takes about ten minutes. It uses the React widget for the
wallet part; without it, see `subscriptions.create` in the
[`@mesub/node` README](https://github.com/Mesub-io/node-sdk#subscribe-from-your-server).

## Step 0: test money on devnet

Test on devnet first. It is the same product, paid in test tokens.

|              | Devnet, to test                                | Mainnet, for real                              |
| ------------ | ---------------------------------------------- | ---------------------------------------------- |
| Dashboard    | [dev.mesub.io](https://dev.mesub.io/dashboard) | [mesub.io](https://mesub.io/dashboard)         |
| API          | `https://api-dev.mesub.io`                     | `https://api.mesub.io`, the SDK's default      |
| Wallet chain | `solana:devnet`                                | `solana:mainnet`, the widget's default         |
| USDC mint    | `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |

The two do not share anything: you sign up to each, and each has its own
projects, plans and API keys. A plan made on dev.mesub.io lives on devnet.
A plan made on mesub.io lives on mainnet. The dashboard links below go to
mesub.io: on devnet, open the same section on dev.mesub.io.

What you need:

1. **Two wallets**, in a wallet app such as Phantom or Solflare, set to
   devnet in its settings. One is yours: it signs the plan and receives the
   money. The other plays your customer.
2. **Devnet SOL** on both, for network fees and rent. Use the
   [Solana faucet](https://faucet.solana.com), or the CLI:

   ```bash
   solana airdrop 1 <WALLET_ADDRESS> --url devnet
   ```

3. **Devnet USDC** on the customer's wallet, from
   [Circle's faucet](https://faucet.circle.com): choose **Solana Devnet**. In
   the plan form on dev.mesub.io, it is the token **USD Coin (devnet)**.

Your code points at devnet in two places. Remove both to go live:

```ts
// Your server: one client for devnet, handed to the routes and guards
// as `client`, e.g. mesubRoutes({ client: mesub, customer }).
const mesub = new Mesub({ baseUrl: 'https://api-dev.mesub.io' });
```

```tsx
// Your page: the wallet signs for devnet.
<MesubProvider endpoint="/api/mesub" chain="solana:devnet">
```

<Steps>
<Step title="Publish a plan">

In the [dashboard](https://mesub.io/dashboard#plans), open **Plans**, then
**New plan**: a name, a price, a token, a period, and the receiving wallet.
To test, a price of 1 USDC charged every day is enough. An
[end](./how-it-works.mdx#an-end-date), a day and a time to the minute in UTC,
is optional.

The organization wallet signs the plan's creation. When you are signed in
with it, the last button is **Sign and publish**. Otherwise it is **Send to
To sign**, and the plan waits there for that wallet.

Mesub derives the plan's **slug** from its name: a plan named Pro gets `pro`.
The slug is how your code names the plan everywhere below. You can read it in
the plan's **Implement** tab, where the code on this page is already filled in
with it.

</Step>
<Step title="Give your server the API key">

In the [dashboard](https://mesub.io/dashboard#developers), open **Developers**,
then **Keys**, and press **Create the key**. The project's API key starts
with `SUB_` and is shown once: [more on the key](./api-key.mdx). Put it in your server's environment:

```bash
MESUB_API_KEY=SUB_...
```

Then install the SDK with your package manager:

```bash
npm install @mesub/node
```

`pnpm add @mesub/node`, `yarn add @mesub/node` and `bun add @mesub/node` work
the same. It goes in `dependencies`: your server needs it in production.

</Step>
<Step title="Mount the routes and gate a route">

Two things on your server. **The routes** are what the widget calls to subscribe
and manage. **The gate** is the question you ask before serving anything paid.
Both need to know who is asking, and that comes from **your own login**.

<CodeGroup>

```ts Express
import { Mesub } from '@mesub/node';
import { mesubRoutes } from '@mesub/node/express';

const mesub = new Mesub(); // reads MESUB_API_KEY

// What the widget calls. Mount it after your own login.
app.use(
    '/api/mesub',
    yourLogin,
    mesubRoutes({
        customer: (req) =>
            req.user ? { external_id: req.user.id } : null,
    }),
);

// A paid route.
app.get('/api/analytics', yourLogin, async (req, res) => {
    if (!(await mesub.hasAccess({ external_id: req.user.id }, 'pro'))) {
        res.status(402).json({ error: 'The Pro plan is needed.' });
        return;
    }
    res.json(buildAnalytics(req.user));
});
```

```ts Next.js
// app/api/mesub/[...mesub]/route.ts: what the widget calls.
import { mesubRouteHandlers } from '@mesub/node/next';

export const { GET, POST } = mesubRouteHandlers({
    customer: async (request) => {
        const session = await yourSession(request);
        return session ? { external_id: session.userId } : null;
    },
});

// app/api/analytics/route.ts: a paid route.
import { withMesub } from '@mesub/node/next';

export const GET = withMesub(
    async (request, mesub) => Response.json(await analytics(mesub)),
    {
        plan: 'pro',
        customer: async (request) => {
            const session = await yourSession(request);
            return session ? { external_id: session.userId } : null;
        },
    },
);
```

```ts NestJS
// main.ts: what the widget calls. Mount it after your own login.
import { mesubRoutes } from '@mesub/node/express';

app.use(
    '/api/mesub',
    yourLogin,
    mesubRoutes({
        customer: (req) =>
            req.user ? { external_id: req.user.id } : null,
    }),
);

// analytics.controller.ts: a paid route.
import { Controller, Get, UseGuards } from '@nestjs/common';
import { MesubAccess, type MesubRequest, RequirePlan } from '@mesub/node/nest';

interface AuthedRequest extends MesubRequest {
    user?: { id: string };
}

@Controller('analytics')
@UseGuards(
    YourAuthGuard,
    RequirePlan<AuthedRequest>('pro', {
        customer: (req) =>
            req.user ? { external_id: req.user.id } : null,
    }),
)
export class AnalyticsController {
    @Get()
    list(@MesubAccess() mesub: MesubAccess) {
        return buildAnalytics(mesub.customer);
    }
}
```

</CodeGroup>

`customer` must come from **a session you verified**, never from what the
browser sends. When it returns `null`, the routes answer 401. The Next.js and
NestJS examples use the SDK's guards, which answer 401 and 402 themselves;
Express has one too, `requirePlan`.

</Step>
<Step title="Put the button on a page">

```bash
npm install @mesub/react
```

It needs `react` and `react-dom` 18 or later. `@mesub/react` 0.1.x works with
the routes of `@mesub/node` 0.1.x: keep the two at the same minor.

Wrap your app once, pointing at where you mounted the routes:

```tsx
import { MesubProvider } from '@mesub/react';
import '@mesub/react/styles.css';

export function App({ children }) {
    return <MesubProvider endpoint="/api/mesub">{children}</MesubProvider>;
}
```

The wallet signs for mainnet by default. For plans on devnet, add
`chain="solana:devnet"`, as in step 0.

Then place the button, with the plan's slug:

```tsx
import { SubscribeButton } from '@mesub/react';

<SubscribeButton plan="pro">Subscribe to Pro</SubscribeButton>;
```

</Step>
</Steps>

## Try it

Sign in to your own site and click the button, with the customer's wallet.
The window shows the plan, asks for a wallet, then for **two approvals**: the
terms, then the first payment. Once it lands, `/api/analytics` answers for
that customer.

You should see:

- the subscription, `active`, under **Subscriptions** in the
  [dashboard](https://mesub.io/dashboard#subscriptions);
- its first payment under **Payments**;
- the price gone from the customer's wallet, and in your receiving wallet.

From here Mesub charges it every period without anything more from you.

Next: [check access](./access.mdx) in detail, and [webhooks](./webhooks.mdx)
to be told when a subscription renews, misses a payment or ends.
