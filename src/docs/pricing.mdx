A tier belongs to a **project**. Its limits count across all the plans of that
project, not per plan.

## Tiers

|                                | Free                | Dev                      | Business                 |
| ------------------------------ | ------------------- | ------------------------ | ------------------------ |
| Price                          | $0                  | $20 a month              | Custom                   |
| Plans                          | 1                   | 3                        | No limit                 |
| Subscribers                    | 30                  | 150                      | No limit                 |
| Automatic retries              | None                | Yes, per plan            | Yes, per plan            |
| Access while a payment is late | Off                 | On, until the last retry | On, until the last retry |
| Retries by hand                | 3 per missed period | Yes                      | Yes                      |

Change tier in the [dashboard](https://mesub.io/dashboard#plans), under
**Plans**.

## What counts

A **plan** counts while it is live: pending, active, or sunset with an end date
still ahead. A failed plan, or one past its end, takes no slot.

A **subscriber** is a wallet with a subscription that is `active`, `unpaid`, or
`cancelled` and not yet past its end. A `stopped` subscription does not count:
it takes a seat again only if it comes back, and only if there is room. A
wallet subscribed to two of your plans counts once.

The dashboard shows both counts under **Plans**, in **Project usage**.

## At a limit

At the plan limit, a new plan cannot be published.

At the subscriber limit, a new subscription is refused with `seat_cap_reached`,
when it is created and again when it is submitted: of several checkouts open on
the last seat, one goes through. Existing subscribers are not affected.

After a downgrade, a project can hold more subscribers than its new tier
allows. The seats over the limit are **parked**: nothing is charged on them,
and their access runs to the end of the period already paid. See
[parked seats](./lifecycle.mdx#parked-seats).

## API rate limits

Limits are per API key, per minute.

| Calls                                                            | Limit          |
| ---------------------------------------------------------------- | -------------- |
| Reads: `/v1/access`, `/v1/plans`, `/v1/subscriptions`            | 1,000 a minute |
| Writes: create, submit, cancel, resume, close and their confirms | 60 a minute    |

Past a limit, Mesub answers 429 `rate_limited` with a `Retry-After` header. The
SDK caches access answers, so one customer checked on every request costs far
fewer calls than requests.

## Other limits

| What                                               | Limit      |
| -------------------------------------------------- | ---------- |
| Webhook endpoints per project                      | 16         |
| Subscriptions waiting for a signature, per project | 1,000      |
| Plans checked by one guard                         | 3          |
| Retries on a plan's own policy                     | 10         |
| Shortest wait between two retries                  | 15 minutes |
